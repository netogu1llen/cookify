Servidor

Servicio de precios · Kotlin 2.3 · Ktor 3.2 · JVM 21 · una instancia sirve a todos los clientes Construido y publicado
RuteoLo único que el cliente ve
ruteo/ GET /api/v1/precios GET /salud ingredientes fuentes supermercados recolecciones StatusPages Validador
HTTP y nada más: parámetros, cuerpos y códigos. 22 rutas bajo /api/v1, cinco recursos y la salud. La lectura es abierta; escribir exige X-API-Key. Ningún error viaja con código 200: StatusPages traduce cada ErrorDelServicio en un solo lugar.
NegocioLas reglas, sin HTTP ni SQL
negocio/ SupermercadoServicio IngredienteServicio FuenteServicio PrecioServicio RecolectorServicio SaludServicio Normalizador
El Normalizador convierte «Arroz Tucapel 1 kg · $2.540» en «arroz · $2,54/g»: saca el formato del nombre, descarta lo que se vende a granel sin peso y toma el percentil 25 de los candidatos de la categoría. El recolector lee categorías y no búsqueda: buscar «cebolla» devuelve mermelada de cebolla y pretzels; la categoría de verduras solo trae verduras.
DatosEl único lugar con SQL

JDBC sin ORM, y el único paquete que habla con jumbo.cl. Cada operación corre dentro de una transacción que abre la capa de negocio, no el DAO: así una regla que toca dos tablas sigue siendo atómica.

Cinco tablas y una vista. Guarda cada corrida en vez de sobrescribir, así se puede responder «cuánto subió el pollo este mes» sin volver a bajar nada. El esquema no lo crea el código: los scripts de db/ son la única fuente de verdad. 183 precios medidos de 196 fuentes mapeadas.
